# Preliminary Technology Stack — Research Candidates Only

**No selected or approved stack.** The developer will propose and defend an initial stack after Level 1–3 RRL findings and technical comparisons are available.

| Layer | Candidates to compare | Reason to investigate |
|---|---|---|
| Web | React / Next.js / Vue | Recruiter dashboard and authorized portals |
| Mobile | Flutter / React Native | Recruiter companion and possible applicant experience |
| Backend/API | FastAPI / Django / Node.js | Auth, workflows, integrations and matching service |
| Database | PostgreSQL and alternatives | Candidates, jobs, applications, audit history |
| Search | SQL/full-text, pgvector if warranted | Rediscovery and candidate retrieval |
| Documents | PyMuPDF, python-docx, Tesseract OCR | Read digital and scanned resumes |
| NLP | spaCy, sentence-transformers, dictionaries | Extract/normalize candidate and job information |
| Matching | Explicit rules, weighted criteria, TF-IDF, embeddings, hybrid | Evaluate relevance, complexity and explainability |
| Authentication | RBAC-compatible approach | Applicant/recruiter/client permissions |
| Hosting | Affordable managed or self-hosted options | Budget, privacy, performance and maintenance |

## Decision criteria
Functional fit; accuracy; explainability; integration; skill availability; documentation; cost; deployment/compute; security; maintainability; data availability; testability.

## Critical warning
These names are **alternatives**, not claims that the cited RRL papers used them. Do not select all tools or imply any combination is already approved.
